## 助手「暂时无法回复」错误兜底太笼统（2026-09-09 21:30）
- **症状**：用户问「这件文物现存于哪里」后浮窗小助手回复「小助手暂时无法回复，请稍后再试」，分不清是网络断、智谱超时还是配额满。
- **根因**：`floating-assistant.tsx` 第 452 行 `catch {}` 块对**所有**失败（fetch throw / res.json 解析失败 / `!res.ok`）都只显示同一句 `assistant.error` 文案，把后端的 `details` 字段（"智谱 GLM 请求超时(40s)" / "429 quota exceeded" 等）吞掉。直接复现接口返回 200，确认那一刻是智谱侧偶发超时/限流，不是代码 bug。
- **修复**：catch 块捕获 `err.message`，按正则分类（`/超时|timeout/i` / `/429|quota|RESOURCE_EXHAUSTED|限流/i` / `/network|fetch|failed/i`）分别用 `assistant.errorTimeout` / `errorRateLimit` / `errorNetwork` 文案；都未匹配则回落通用 `assistant.error`。三语（zh-CN/zh-TW/en）各补 3 个键。
- **教训**：用户能看到的错误文案绝不能「一锅端」——把可识别的失败原因分类展示，下次用户能自己判断是等、重试还是换问法，而不是对着同一句「稍后再试」摸不着头脑。
  3. **教训：测试后端校验别用会改变真实数据的小输入**。我先用 `head -c 30` 测合法 data URI，结果把 30 字节垃圾写进了 DB，又得从备份恢复一次。验证校验应当用「会被拒的输入」+ 「只读端点」，需要写库时先做备份或换 demo 数据。
