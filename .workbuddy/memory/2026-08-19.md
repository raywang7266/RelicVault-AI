# 2026-08-19 工作记录

## 修复登录 `fetch failed`（任务：登录接口内部抛出 fetch failed）

**根因**：`src/actions/auth.ts` 的 `signIn` 是 Server Action，内部直接 `supabase.auth.signInWithPassword(...)`，而 `.env.local` 仍是占位 Supabase 地址，且**没有 try/catch**——网络异常向上冒泡成未捕获错误，前端表现为 `fetch failed`。

**改动**：
- 新增 `src/lib/supabase/config.ts`（`isSupabaseConfigured()`）、`src/lib/auth/types.ts`、`src/lib/auth/mock-session.ts`（cookie 编解码，isomorphic）、`src/lib/auth/core.ts`（authenticate/registerUser/signOutUser，统一 try/catch + `console.error` 打印 `error.message` 与 `error.cause`，并支持 Mock 模式）。
- 新增 REST 路由 `src/app/api/{login,register,logout}/route.ts`：登录/注册走 `fetch('/api/...')`，先判 `response.ok` 再安全解析 JSON；解析失败返回 400，不再崩溃。
- `src/components/auth/auth-form.tsx`：由 `useFormState` 改为 `fetch` 提交，仅 `ok && 解析成功` 才跳转，否则给可读提示。
- `src/lib/auth/server.ts` 的 `getServerUser()`：先读 `rv_mock_session` cookie，否则回退 Supabase；供根布局、页面、导航栏初始态使用。
- `src/middleware.ts`(lib) / `use-user.ts`：`isSupabaseConfigured()` 为 false 时**完全不发起网络请求**（读本地 cookie 判登录态），避免浏览器与中间件也抛 `fetch failed`。
- 根布局 `src/app/layout.tsx` 向 `<Navbar initialUser={user} />` 注入服务端用户态；`header.tsx` 登出改为 `fetch('/api/logout')`。
- `dashboard`、`artifacts/new` 两页改用 `getServerUser()`。

**附带修复**：`artifacts/new` 页面原先把内联 `handleSubmit` 当 prop 传给客户端组件，触发 `Event handlers cannot be passed to Client Component props` 的 500。已抽出 `src/actions/artifact.ts` 的 `submitArtifact` Server Action 传入。

**验证**：`npm run typecheck` ✅、`npm run build` ✅（19 路由 + 中间件）。本地起服务：
- `/api/login` 有效凭证 → 200 + 写入 `rv_mock_session`；Mock 下任意合法邮箱/密码可登录。
- `/dashboard`、`/artifacts/new` 带 cookie → 200；不带 → 307 跳 `/login`。
- 非法 JSON / 非法格式 → 400 且返回可读错误，不崩溃。

**注意**：构建时仍需 `CODEBUDDY_SESSION_ID= CLAUDE_SESSION_ID= npm run build`（沙箱 safe-delete 拦截 .next 清理）。
