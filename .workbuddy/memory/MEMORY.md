- **入场动画铁律（踩过坑）**：**永远不要在静态 CSS 里把元素的 `opacity` 写成 0，然后指望 `animation-fill-mode: both` 在动画结束时用关键帧 100% 把它拉回 1。** 这套写法在「DevTools 的 prefers-reduced-motion 切换 / HMR 重新挂载 / React StrictMode 双调用 / CSS multi-column + break-inside-avoid 叠加」等情况下，fill-mode 会被剥离 → 元素永久 opacity:0 → DOM 在、计数对、视觉完全空白且无 console 报错。**正确做法**：关键帧 0% 不带 opacity，只用 transform 入场（`translateY` / `scale`），元素默认始终可见。已应用此规则于 `tailwind.config.ts` 的 `fade-in` / `fade-in-up` 关键帧与 `globals.css` 的 `@keyframes stagger-rise`。
- **入场动画第二铁律（display:contents 把动画打死）**：`display: contents` 元素**不生成 box**，所以 **`transform` / `animation` / `width` / `height` / `position: relative`** 等依赖 box 的 CSS 属性**完全不生效**。**禁止**用 `<div className="contents">` 包裹 grid/flex 子元素来「加 wrapper 但保持布局」——动画会失效。需要「不破坏外层 grid/flex」时直接让子元素成为直接子元素、把样式加在外层即可。
- **Tailwind 动画第三铁律（@keyframes 必须写在 @layer 之外）**：**所有 `@keyframes` 定义必须写在 `@layer utilities` / `@layer components` 之外（文件末尾）**。写在 `@layer` 内部的 `@keyframes` 会被 Tailwind/PostCSS 构建时剪裁、**根本不输出到浏览器加载的 CSS** → 动画引用了不存在的关键帧 → 永不播放且无报错。`.reaction-*` 工具类可以写在 `@layer utilities`，但 `@keyframes` 定义必须移到 `@layer` 外（参考 `globals.css` 末尾的 `@keyframes stagger-rise`）。**验证「动画不播放」的正确姿势**：直接用 `npx tailwindcss -i src/app/globals.css -o /tmp/x.css --content "src/**/*.{ts,tsx}"` 编译，grep 产物里的 `@keyframes xxx` 关键字本身——只 grep class 选择器会误判（类在、关键帧不在）。
