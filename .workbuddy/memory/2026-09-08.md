**现象**：用户点 Profile 任一笔记的「编辑」→ 弹窗不出现，整页直接崩进错误边界（「这个页面出了点问题」）。

## 2026-09-08 傍晚：评论功能失效 —— Zod 拒收 `parentId: null`（根因 + 修复）

**现象**：用户在文物详情页发评论 → 弹「评论失败」toast，评论发不出去（截图为错误提示）。

**排查**：用 agent-browser（已装 Chromium，位于 `node_modules/agent-browser/bin/agent-browser-win32-x64.exe`）真实复现：浏览器 network 显示 POST `/api/artifacts/[id]/comments` 返回 **400**，而 curl 发同请求返回 201。差异在于前端 `fetch` body 恒带 `"parentId": null`（非回复时），后端 Zod `parentId: z.string().optional()` **只放行 undefined 不接受 null** → 验证失败 400，被 catch 转成「评论失败」。

**根因**：`src/app/api/artifacts/[id]/comments/route.ts` 的 bodySchema 把 `parentId` 写成 `.optional()`（不含 nullable）。前端对顶层评论总是传 `parentId: null`（reply 才传字符串），导致所有「直接评论」被 400 拒收。

**修复**：`parentId: z.string().nullable().optional()`（加注释说明前端恒带该字段、null 即顶层）。

**验证**：tsc 0 / build 成功 / root rm + cp + restart。浏览器复现：修复后发评论，评论数 (1)→(2)、不再弹「评论失败」。node 接口验证：POST 带 `parentId:null` → **201** `{ok:true}`。

**清理**：浏览器测试期间产生的 3 条测试评论（文案含「浏览器自动化/修复后验证/接口验证评论」等）经 `docker exec relicvault-mongo mongosh` 对 `relicvault.artifacts` 该文物 `$pull {comments:{text:正则}}` 移除，恢复为 1 条原始演示评论；无残留。

**铁律补充**：Zod `.optional()` 不等于「可空」——前端可能传 `null`（尤其「非必填但总在 body 里」的字段如 parentId、imageUrl）。凡前端恒带、缺省为 null 的字段，schema 用 `.nullable().optional()`，否则生产必炸。

## 2026-09-08 晚（续）：字号调节修正 —— 必须「只缩放文本」而非整体缩放

**用户反馈**：上一版缩放根字号（`html{font-size:calc(100%*var(--font-scale))}`），因 Tailwind 间距/图标/边框全用 rem，结果整页等比放大 = 浏览器整体缩放，用户明确反对「这只是页面放大缩小，不是文本大小改变」。

**根因**：把 `--font-scale` 作用于根字号基准，误伤了所有 rem 量（padding/margin/gap/width/height/icon）。

**修正（只让字号乘变量，间距/尺寸纹丝不动）**：
- `globals.css`：删除 `html{font-size:...}` 规则，仅保留 `:root{--font-scale:1}`；`.eyebrow`、`.reaction-fly` 的 `font-size` 改为 `calc(Npx*var(--font-scale))`。
- `tailwind.config.ts`：`theme.extend.fontSize` 全部 token 重写为 `calc(<base>rem * var(--font-scale))`，行高用无单位倍数（随字号自动放大）。
- 写死的 48 处 `text-[Npx]`：用 `tmp/scale-text.js`（正则 `text-\[(\d+)px\]`→`text-[calc($1px*var(--font-scale))]`）批量改写，覆盖全部正文/徽章/标题；改后 grep 确认 0 处残留。
- `user-avatar.tsx`：头像首字母 `style.fontSize` 改为 `calc(...px*var(--font-scale))`（控件自身预览 px 故意不缩放）。
- `font-size-control.tsx` 控件逻辑未动（仍写 `--font-scale` + localStorage）。

**E2E 验证（agent-browser，curator 登录 /explore）**：
- root 字号：标准/特大 均 **16px**（不再变 → 证明不是整体缩放）。
- 卡片标题文字：`15px` → `20.25px`（15×1.35，文本变大）。
- `px-2` 内边距：`10px` → `10px`（不变，布局不撑大）。
- localStorage `rv_font_scale`="1.35" 持久化。
- 编译 CSS 全量 grep：`var(--font-scale)` 共 18 处、全部挂在 `font-size`（及配套 line-height），**0 处**出现在 padding/margin/gap/width/height。

**铁律（新增）**：字号调节类需求——严禁缩放根字号（那等于浏览器缩放）。正确做法：仅 Tailwind `fontSize` 标度 + 写死 px 文本 乘 `--font-scale`；间距/尺寸一律不动。

**根因**：控件用 `text-sm` 标签按钮，而 `text-sm` 会随 `--font-scale` 放大 → 1.9× 时按钮文字 26px+、整段控件变宽变高，撑破固定 `h-16` 的导航栏。

**修复（统一为「固定尺寸图标按钮」工具栏）**：
- `globals.css` 新增 `@layer components` 的 `.rv-controls`（圆角胶囊容器：parchment 底 + backdrop-blur + 柔阴影）与 `.rv-ctrl`（36px 圆形图标按钮，`position:relative`，`text-[var(--muted)]`，hover 变深青铜字 + `bg chip` + 金色描边光晕 `box-shadow:0 0 0 1px var(--gold)...` + 图标 `scale-110`；`[data-theme=dark] svg` 加暖金 `drop-shadow` 光晕；`.rv-ctrl-lang:hover svg` 地球 `rotate(18deg) scale`；`.rv-ctrl-badge` 当前档位百分比小角标 `bg-[var(--gold)]`，固定 8px 不缩放）；`.rv-menu` / `.rv-menu-item` 主题感知下拉（圆角 x + `bg-[var(--card-bg)]` + `hover:bg-[var(--chip)]`，选中 `text-[var(--bronze)]`）。
- 三组件改为纯图标按钮（去掉文字标签，靠 `title` tooltip + 角标提示）：`theme-toggle.tsx`（`rv-ctrl` + `data-theme`，Sun/Moon 18px）；`font-size-control.tsx`（`rv-ctrl` + 角标显示 `scale×`，下拉用 `.rv-menu/.rv-menu-item`）；`language-switcher.tsx`（`rv-ctrl rv-ctrl-lang` + Globe，`ChevronDown` 弃用已删 import）。
- `header.tsx`：三控件包进 `<div className="rv-controls">` 胶囊，外层 `flex gap-2 sm:gap-3`。

**为什么顺便修了溢出**：图标按钮尺寸写死 36px（`h-9 w-9`，不随 --font-scale），所以无论字号多大，控件 chrome 高度恒定，不会再撑高导航栏；同时去掉文字标签大幅收窄了控件宽度，避免横向溢出。

**E2E（agent-browser，curator）**：`.rv-controls` 存在、含 3 个 `.rv-ctrl`；点主题→`dark` true；选「极大」→ `--font-scale=1.9`、角标 `1.9×`；**`.rv-ctrl` 高度恒 36px**；`headerH=66, ctrlBottom=56, overflow=-10`（控件在导航栏内 10px）、整段右集群 `overflow=-1`。溢出已修复。

**铁律补充（控件 chrome 不缩放）**：导航栏/工具栏等「界面控件」自身的文字与尺寸须用**固定值**（如 `text-[13px]`、`h-9 w-9`），绝不能依赖会乘 `--font-scale` 的 `text-sm` 等 token——否则用户把字号调到最大会撑破导航栏。用户主动调节的是「正文」，控件 chrome 应始终稳定。
