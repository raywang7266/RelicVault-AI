## 探索页瀑布流卡片完全空白（计数 14 但区域空白）

**症状**：截图显示 `共 14 件 · 14 件含出土地理位置`，但瀑布流区一片白，没有骨架、没有 empty 提示、报错也没。

**根因**：之前给 `.stagger-fade` 加的入场动画是这样的：

```css
.stagger-fade > * {
  opacity: 0;                       /* 静态 0 */
  animation: fade-in-up 0.5s ... both;  /* fill-mode both 靠关键帧回到 1 */
}
```

这套写法依赖 `animation-fill-mode: both` 在动画结束时把子元素从 opacity:0 拉到关键帧 100% 的 opacity:1。**任何让 fill-mode 失效的因素**（prefers-reduced-motion（HMR/StrictMode 下重新挂载时 fill-mode 被剥离）、CSS multi-column 与 `break-inside-avoid` 叠加、HMR 重新挂载）都会让子元素**永久停在 opacity:0**——DOM 在那里（计数对了），视觉完全空白，且没有任何控制台报错。

**修复**：删掉所有「静态 `opacity:0` + `animation: ... both`」这套易碎的入场动画实现，统一改为**只用 transform（translateY）+ 不依赖 fill-mode 把 opacity 从 0 拉到 1**：

- `tailwind.config.ts`：`fade-in` / `fade-in-up` 关键帧从 `0% { opacity:0 } → 100% { opacity:1 }` 改为纯 transform。
- `globals.css`：新增 `@keyframes stagger-rise`（替代暴露问题的 fade-in-up），`.stagger-fade > *` 用 CSS 变量 `--stagger-delay` 给每个 nth-child 不同延时，**彻底拿掉静态 `opacity:0`**。
- 这样即使动画被运行环境剥离，子元素也是默认可见状态，不会「隐形」。

**教训（要进 MEMORY 主索引的）**：写页面入场动画时，**永远不要在静态 CSS 里把元素的 opacity 设成 0 然后指望 `animation-fill-mode:both` 把它拉回来**。要么关键帧里 0% 不带 opacity（用 transform-only 入场），要么用 React 状态（visible flag）控制初始可见性。这条规则适用于 `.stagger-fade`、toast banner、main wrapper、Drawer/Sheet 等任何用入场动画的位置。

**验证**：`curl /api/artifacts?limit=50` 仍返回正常数据；编译后 `.next/static/css/app/layout.css` 时间戳已更新（14:19），产物里 `.stagger-fade > * { animation: stagger-rise 0.5s ... both }` 不再有 `opacity: 0` 静态声明，`@keyframes stagger-rise` / `fade-in` 都只动 transform；`tsc --noEmit` 干净。

## 「profile 我的贡献」动画完全失效——display:contents 把动画打死了（14:50）

**症状**：用户反馈上一轮改的三个动效「还没生效」，并贴了一张 favicon.ico 404 的 Console 截图（42 Issues、2 hidden）。

**真凶**：`src/components/profile/profile-view.tsx` 的「我的贡献」网格我之前为了避免被 stagger-fade 干扰 grid 布局，加了一层 `<div className="contents">` 包裹：

```jsx
<div className="grid ... stagger-fade">
  <div className="contents">          ← 问题就出在这
    {uploads.map(a => <UploadCard ... />)}
  </div>
</div>
```

**为何动画失效**：
- `.stagger-fade > *` 选择的是那个 `.contents` 元素（它是唯一直接子元素）。
- `display: contents` 元素**不生成 box**，所以 `animation: stagger-rise ... { transform: translateY }` 这种依赖 box 的动画**完全无效**。
- 而原本的「探索页瀑布流」用的是 `columns-` 多列布局，卡片是 `.stagger-fade` 的直接子元素，所以动画工作得很好。
- 这就是为什么用户能看到探索页动画、看不到 profile 页动画——只有这一处错用 `.contents` 包裹。

**修复**：去掉那层 `<div className="contents">`，让 `stagger-fade` 直接当 grid 容器，`UploadCard` 直接是 grid item（直接子元素），动画立即生效。

**教训（要进 MEMORY 主索引的）**：
- `display: contents` 元素**不生成 box**，因此 **`transform`、`animation`、`width`、`height`、`position: relative`** 等依赖 box 的 CSS 属性都不会生效。
- 需要「不破坏外层 grid/flex 布局但加 wrapper」的常见需求，用 `display: contents` 通常是错的——要么直接把样式加在外层、要么放弃 wrapper。
- 排查「动画不工作」时第一时间检查：父容器和被动画元素之间有没有 `display: contents`、有没有 `position: fixed/absolute` 抽出流的子元素、有没有 `Portal` 渲染。

**附带修了 favicon 404**：加 `src/app/icon.svg`（项目主题色 #8C6D46 古铜色徽章 SVG），并在 `layout.tsx` 的 metadata 里加 `icons.icon`，Next.js 会自动提供 `/icon.svg`，浏览器拉不到 `/favicon.ico` 也不再报 404。

**验证**：`tsc --noEmit` 干净；dev server 日志显示 `✓ Compiled in 1989ms (1021 modules)`（profile 模块被重编译），`GET /icon.svg 200 in 1719ms`。

## 登录按钮"弹跳循环"修复——陈旧会话 cookie + 全新空库（21:36）

**症状**：用户 Docker 启动全新 MongoDB 后，点导航栏「登录」直接被弹到 /explore，之后所有按钮（个人中心等）都"没用"。

**根因**：浏览器残留旧 `rv_session` cookie（JWT 签名仍有效、7天有效），但 Docker 空库里无此用户。两套判断标准打架：middleware 只验 JWT 签名→认为已登录→把 /login 弹去 /explore；页面/导航栏查库→认为未登录→显示「登录」按钮、/profile 守卫跳 /login。用户被锁死在 /login↔/explore 循环里，永远到不了登录表单。

**修复（3 处，tsc 通过 + curl 4 项验证通过）**：
1. `src/lib/auth/middleware.ts`：删掉「已登录访问 /login、/register 就 redirectToExplore」的中间件逻辑（edge 层无 mongoose 查不了库，无法分辨真登录/陈旧会话）。
2. `src/app/(auth)/login/page.tsx` + `register/page.tsx`：改为 async 服务端组件，`getSessionUser()` 查库——真用户才 `redirect("/explore")`；陈旧 cookie 正常渲染表单，重新登录后 createSession 覆盖旧 cookie。
3. `src/app/api/me/route.ts`：陈旧会话自愈——`getSessionUserId()` 非空但 `getSessionUser()` 为 null 时，在 Route Handler 里 `cookies().delete(SESSION_COOKIE)`（Server Component 无权改 cookie，Route Handler 可以）。导航栏每页都调 /api/me，所以任何页面加载一次即自愈。

**验证方法（可复用）**：用 node + jose 按 .env.local 的 SESSION_SECRET 签一个 sub 指向不存在 ObjectId 的 token，curl 带 `Cookie: rv_session=<token>` 打 /login——修复前 307→/explore，修复后 200；/api/me 响应头出现 `set-cookie: rv_session=; Expires=1970`。

**教训（要进 MEMORY 主索引的）**：JWT 无状态会话 + 换库/清库场景必然出现"签名有效但用户不存在"的僵尸会话。「已登录跳过登录页」这类决策不能放在只验签名的 middleware 层，必须放到能查库的页面层；且要在 Route Handler 里做陈旧会话清除自愈。

## 导航栏登录后仍显示未登录（2026-08-23 晚）

根因：Navbar 挂在 **root layout**（`src/app/layout.tsx`，不在 `(main)/layout.tsx`），登录成功后 `router.push("/explore")` 是客户端软导航，root layout / Navbar **不会重新挂载**；而 `useUser` 的 `useEffect(deps:[])` 只在挂载时请求了一次 `/api/me`（当时未登录），`useState(initialUser)` 也不跟随 prop 更新 → 导航栏卡死在未登录快照，硬刷新才恢复。
修复（`src/hooks/use-user.ts` 重写）：
1. `useEffect(deps:[pathname])` —— 挂载 + **每次路由切换**都重新拉 /api/me（登录后 push 到 /explore 触发）；
2. `useEffect(deps:[initialUser])` —— `router.refresh()` 让 root layout 重渲染传入新用户时显式同步 state；
3. 网络异常时保留当前状态（不再回退可能过期的 initialUser）；
4. `header.tsx` 骨架屏改为 `isLoading && !user` 才显示，避免已登录用户每次切页闪骨架。
验证：curl 带 cookie 打 /explore，SSR HTML 含 curator 邮箱 + 退出按钮（服务端链路本来就通）；tsc 通过。**教训**：跨路由持久的布局组件（root layout 里的 Navbar）里的会话状态，必须挂 pathname 依赖或全局 store，不能只在 mount 时拉一次。
