## 纯 Docker 启动整套服务（新增 Dockerfile / docker-compose.yml / .dockerignore）

**背景**：用户要用 Docker 启动网页，且反馈 README 指引不明确。

**关键发现**：当前分支 `feat/lan_category_fix` 的 README 还停留在 Supabase + OpenAI 时代（Prerequisites 写 Supabase 项目、Database Setup 写 `supabase db push`），与现在 MongoDB + Zhipu GLM 的代码完全不匹配。之前会话改过的 README（MongoDB 安装、演示数据、Zhipu 密钥章节）在分支切换/工作区重置中丢失（git working tree clean，分支与旧快照一致）。

**新增文件**：
- `Dockerfile` — 3 阶段构建 `node:22-slim`：deps(`npm ci`) → builder(`npm run build`) → runner(只拷 `package.json`/`node_modules`/`.next`/`public`/几个配置文件，`USER node`，`CMD npm start`)。
- `docker-compose.yml` — `mongo:7`(healthcheck 用 mongosh ping) + `app`(build context 当前目录)。要点：
  - app 用 `env_file: .env.local`，但用 `environment: MONGODB_URI: mongodb://mongo:27017/relicvault` 覆盖（容器内 localhost 是自身）。
  - Mongo 宿主机端口映射 **27018**（27017 通常被本机 mongod 占用，会 port is already allocated）。
  - 数据卷用 `volumes: relicvault-mongo-data: name: relicvault-mongo-data` 固定名字 → 复用旧数据卷，避免 compose 加项目前缀。
- `.dockerignore` — 排除 node_modules/.next/.git/.workbuddy/tmp/测试/**`.env.local`（密钥经 env_file 运行时注入，不进镜像）。

**验证结论（重要）**：`next build` **不需要数据库**。所有路由都是 ƒ (Dynamic)（root layout 读 cookies 导致全站按需渲染），只有 `/icon.svg` 是静态。所以 Docker build 阶段无 DB 也能成功。

**踩坑**：
1. 沙箱无法启动 Docker Desktop（`.docker/daemon.json`/`config.json` 被策略拦截；WSL/tasklist 等系统工具也被禁）。→ 让用户手动开 Docker Desktop，再用 python 轮询 `docker ps` 直到 ready。
2. `docker rm -f relicvault-mongo` 才能释放容器名——之前手工 `docker run --name relicvault-mongo` 留下的容器会让 compose up 报 Conflict。**注意：`docker rm -f` 不会删命名卷，数据保留**。
3. `genie-safe-delete` 对本工作区路径会失败（路径 canonicalize 错误），`rm` 被拦截失败 —— 临时文件改用 `mv` 到 `tmp/`。
4. `sleep` 命令在此 bash 环境不可用，轮询等待用 python `time.sleep`。

**启动结果**：`relicvault-app`(3000) + `relicvault-mongo`(27018, healthy) 均 Up；`/login` 200、`/explore` 未登录 307、`/api/artifacts` 返回 14 条；演示账号 `curator@relicvault.app` / `RelicVault@2026` 经 Docker 容器内登录成功。

**README 改动**：重写 Getting Started（Option A Docker 优先：前置检查 `docker ps` → 建 `.env.local` → `docker compose up -d --build` → 开 3000；Option B Node+Mongo 简版）、环境变量表改为当前变量、新增「Get a Zhipu GLM API key (required)」与「Demo data (seeded automatically)」、新增 Troubleshooting 表（daemon 未启动/端口占用/容器名冲突/密钥缺失/陈旧会话跳转）、架构图改为 MongoDB + Zhipu + compose 拓扑图、新增「Data Model」章节并把 Supabase 旧 schema 标为 Legacy（仅参考）、目录树加入 Dockerfile/compose/.dockerignore、`src/lib` 表更新为 `mongodb.ts`/`store/`/`models/`/`vision/`/`auth/`。
