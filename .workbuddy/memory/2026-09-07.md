**背景**：用户要用 Docker 启动网页，且反馈 README 指引不明确。

- `Dockerfile` — 3 阶段构建 `node:22-slim`：deps(`npm ci`) → builder(`npm run build`) → runner(只拷 `package.json`/`node_modules`/`.next`/`public`/几个配置文件，`USER node`，`CMD npm start`)。

1. 沙箱无法启动 Docker Desktop（`.docker/daemon.json`/`config.json` 被策略拦截；WSL/tasklist 等系统工具也被禁）。→ 让用户手动开 Docker Desktop，再用 python 轮询 `docker ps` 直到 ready。

## 2026-09-07 夜：AI 识图失败排查与修复（智谱图片体积上限）

**现象**：用户登录后点「AI 识图」失败。

**排查（逐项排除，均正常）**：
- 容器内 `fetch` 智谱 API：HTTP 400（非 401）→ 网络通、key 有效。
- `/api/ai/analyze` 是 501 占位；前端实际调 `/api/analyze-artifact`（正确）。
- 端到端：400x300 PNG、5.41MB JPEG、WEBP、连续 6 次调用 → 全部 200（无限流）。

**根因**：**图片 base64 体积超智谱 GLM 上限（约 10MB）**，与分辨率无关。
- 关键对照实验：4000x5000 但仅 4.19MB（base64 5.59MB）→ **成功**；9.37MB（base64 12.49MB）→ **失败**（智谱返回「API 调用参数有误」→ 接口 502）。
- 前端 `processFile` 允许最大 10MB 原图 → base64 膨胀约 1.33 倍 → 13MB → 必失败。手机原图极易命中。

**修复**：
- `ArtifactUploadForm.tsx`：新增 `compressImageForAI()`（浏览器 canvas，最长边缩到 2048 + JPEG 质量 0.85 起每档 -0.15 递减压到 ≤4MB，先铺白底防 PNG 透明变黑；失败回退原图）。`handleAIAnalyze` 发送前调用，**不改动 `imagePreview`**（提交保存仍用原图）。
- `api/analyze-artifact/route.ts`：兜底——`dataUrl.length > 10MB` 直接返回 **413 +「图片过大…请压缩或裁剪后重试」**，替代含糊的 502。

**验证**（Docker 重建后）：超大原图 → 413 明确提示；压缩后（1.72MB / base64 2.30MB）→ 200 正常识别。
